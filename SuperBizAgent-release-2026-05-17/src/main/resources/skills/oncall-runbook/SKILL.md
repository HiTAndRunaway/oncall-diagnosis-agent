# 运维处置手册（Oncall Runbook）

本技能提供常见运维告警的标准处置流程。收到告警时按对应场景执行，先看结论再看详细步骤。

## 使用方式

- 直接调用本技能：模型会通过 read_skill 加载完整手册。
- 每个场景的详细排查步骤见 references/ 目录下的对应文档。

## 五大告警场景速查

| 告警 | 首要动作 | 关键指标 |
|------|---------|---------|
| CPU 高负载 | 定位 top 进程，检查是否存在死循环/突发流量 | cpu usage > 85% 持续 5 分钟 |
| 内存高负载 | 检查 OOM 风险进程与内存泄漏 | mem usage > 85% 或 swap 持续增长 |
| 磁盘高负载 | 定位大文件/日志，评估清理或扩容 | disk usage > 85% |
| 服务不可用 | 检查进程存活、健康检查、依赖服务 | 探活失败次数连续 3 次 |
| 响应缓慢 | 定位慢 SQL/慢接口，检查连接池 | P95 延迟 > 3s |

## 通用原则

1. 先止损：必要时重启服务或摘流量，再定位根因。
2. 证据优先：所有结论必须有监控数据支撑。
3. 恢复后跟进：记录时间线、根因、改进项，防止复发。
4. 不确定时优先参考对应 references 文档，不要凭经验猜测。
