# 重排序（Rerank）方案设计

> 状态：✅ 已确认 | 日期：2026-07-07

---

## 一、背景与目标

当前 RAG 管线在 Milvus 向量检索后直接将结果返回给 Agent 或喂入 LLM。向量相似度（L2 距离）在语义精度上有局限，当召回文档较多时，需要引入**精确重排序**来提升 top 文档的相关性。

**核心规则：**
1. 召回 chunk 数 ≤ 10：不重排序，直接返回
2. 召回 chunk 数 > 10：调用 DashScope Rerank API 重排序，筛选 top 10

**技术选型：** 阿里云 DashScope Rerank API（`gte-rerank` 模型），与现有 DashScope 生态一致。

---

## 二、整体架构与数据流

重排序作为 `VectorSearchService.searchSimilarDocuments()` 内部的后处理步骤，对上层调用方（`InternalDocsTools`、`RagService`）完全透明。

```
用户查询
   ↓
VectorSearchService.searchSimilarDocuments(query, topK)
   │
   ├─ 1. 查询向量化 (embeddingService.generateQueryVector)
   │
   ├─ 2. Milvus 检索 (用 recallCount 条，而非 topK)
   │
   ├─ 3. 判断：结果数 > threshold(10) ?
   │      │
   │      ├─ 否 → 截取 topK 条直接返回
   │      │
   │      └─ 是 → 调用 DashScope Rerank API
   │               传入 query + 所有文档内容
   │               按 relevance_score 降序取 top 10
   │               API 失败则降级：warn 日志 + 原始结果截取
   │
   └─ 4. 返回最终结果 (List<SearchResult>)
```

**涉及文件：**
| 文件 | 改动类型 |
|------|---------|
| `VectorSearchService.java` | 核心改动 |
| `application.yml` | 新增配置项 |

## 三、配置变更

在 `application.yml` 的 `rag` 块下新增：

```yaml
rag:
  top-k: 3                    # 现有：最终返回数量
  model: "qwen3-max"          # 现有：LLM 模型
  
  # 新增：重排序相关配置
  recall-count: 30            # Milvus 初始召回数量
  rerank:
    enabled: true             # 是否启用重排序
    threshold: 10             # 触发阈值：召回数 > 此值才重排序
    top-k: 10                 # 重排序后保留的文档数
    model: "gte-rerank"       # DashScope Rerank 模型名称
```

**参数关系：**
- `recall-count`：Milvus 检索时实际使用的 topK，应大于 `rerank.threshold`（否则重排序永不触发）
- `rerank.threshold`：结果数超过此值才触发重排序
- `rerank.top-k`：重排序后保留的数量
- `topK`：不触发重排序时的最终返回数量

**注意：** 如果 `rerank.enabled=false`，行为与现在完全一致。

## 四、VectorSearchService 改动

### 4.1 新增字段

```java
@Value("${rag.rerank.enabled:true}")
private boolean rerankEnabled;

@Value("${rag.rerank.threshold:10}")
private int rerankThreshold;

@Value("${rag.rerank.top-k:10}")
private int rerankTopK;

@Value("${rag.rerank.model:gte-rerank}")
private String rerankModel;

@Value("${rag.recall-count:30}")
private int recallCount;
```

### 4.2 searchSimilarDocuments 方法调整

方法签名不变 `(String query, int topK)`，内部逻辑调整：

```java
public List<SearchResult> searchSimilarDocuments(String query, int topK) {
    // 1. 向量化（不变）
    List<Float> queryVector = embeddingService.generateQueryVector(query);

    // 2. Milvus 检索：开启重排序时用 recallCount，否则用 topK
    int fetchCount = rerankEnabled ? recallCount : topK;
    // ... SearchParam 中 withTopK(fetchCount)，其他不变

    List<SearchResult> results = executeSearch(...);

    // 3. 重排序判断
    if (rerankEnabled && results.size() > rerankThreshold) {
        results = rerank(query, results);
    } else if (results.size() > topK) {
        results = results.subList(0, topK);
    }

    return results;
}
```

### 4.3 新增 rerank 私有方法

```java
private List<SearchResult> rerank(String query, List<SearchResult> documents) {
    try {
        logger.info("触发重排序，召回: {}, 阈值: {}", documents.size(), rerankThreshold);

        // 1. 构建 documents 列表（DashScope Rerank API 格式）
        List<Map<String, String>> docMaps = documents.stream()
            .filter(d -> d.getContent() != null && !d.getContent().isEmpty())
            .map(d -> Map.of("content", d.getContent()))
            .toList();

        // 2. 调用 DashScope Rerank API
        //    使用 dashscope SDK 的 Rerank 能力
        //    参考: com.alibaba.dashscope 包
        RerankParam param = RerankParam.builder()
            .model(rerankModel)
            .query(query)
            .documents(docMaps)
            .topN(rerankTopK)
            .build();
        RerankResult result = rerankClient.call(param);

        // 3. 按 relevance_score 降序组装结果
        //    保留原始 SearchResult 中的 id, content, metadata
        //    用 relevance_score 覆盖原始 L2 score

        logger.info("重排序完成，返回: {}", rerankTopK);
        return rerankedResults;

    } catch (Exception e) {
        // 降级：返回原始排序的前 topK
        logger.warn("Rerank API 失败，降级使用原始排序: {}", e.getMessage());
        int limit = Math.min(rerankTopK, documents.size());
        return documents.subList(0, limit);
    }
}
```

## 五、错误处理与边界情况

| 场景 | 处理策略 |
|------|---------|
| Rerank API 调用失败 | 降级：warn 日志 + 返回原始结果截取 |
| Rerank API 超时 | 同上降级，建议超时 5s |
| 召回结果为空 | 直接返回空列表，不触发重排序 |
| 召回结果 ≤ threshold | 跳过重排序，按 L2 分数截取 topK |
| 重排序返回数 < 预期 | 以实际返回为准 |
| 文档内容为 null/空 | 过滤后再送入 Rerank API |
| `rerank.enabled=false` | 行为完全不变 |
| `recallCount ≤ threshold` | 启动时 warn 日志提示配置不合理 |
